# Believe (PWA React + TypeScript)

## Démarrer
`npm install`, puis `npm run dev` (développement), `npm run typecheck` (application et fonctions serveur `api/`), `npm run build` (production).
Contrôles : `npm run audit` (calculs, migration des données, import, persistance, PIN, IndexedDB, fonctions serveur avec appels simulés ; à lancer aussi avec `TZ=America/Los_Angeles` et `TZ=Pacific/Auckland`) `npm test` (parcours d'interface simulés avec jsdom), `node scripts/contrast.mjs` (contrastes WCAG des 3 thèmes), `npm run verify:verses` (texte des versets, voir « Rubriques 1, 2 et 4 ») et `npm run build && npm run e2e` (parcours dans un vrai Chromium avec faux micro, IndexedDB réel, service worker, en-têtes de sécurité et CSP réellement appliqués, balayages tactiles et contrôle d'accessibilité axe-core ; les réponses des catalogues de livres et de l'IA y sont simulées par interception réseau). Les tests de bout en bout refusent de démarrer si un ancien serveur occupe déjà le port 4173 (`pkill -f "vite preview"`).
Non testé : appareils réels (GPS, podomètre, vibration, vraie voix pour la dictée, notifications du système, installation iOS et Android), appels réels à Gemini (texte, photos et images de plats : la requête d'image suit la documentation de Google mais n'a jamais été envoyée au vrai service), à YouTube et aux catalogues de livres (Open Library, Google Books, Project Gutenberg, LibriVox : les analyseurs de réponses sont vérifiés sur des réponses simulées), compteurs partagés Upstash/Vercel KV.

## Déployer (Vercel, gratuit) : requis pour l'installation PWA (HTTPS) et les fonctions serveur
1. Poussez le dossier sur GitHub et importez-le dans Vercel (preset Vite).
2. Variables d'environnement :
   - `GEMINI_API_KEY` (IA) : clé créée dans Google AI Studio ;
   - `AI_MODEL` (optionnel) : défaut `gemini-3.5-flash`, à changer si Google retire ce modèle (erreur « Modèle introuvable ») ;
   - `AI_IMAGE_MODEL` (optionnel, image du plat des recettes) : défaut `gemini-nano-banana-2.1`, à changer si Google le retire ; `AI_IMAGE_DAILY_LIMIT` : images par jour et par personne, **20 par défaut**. La création d'image est **payante** (pas de palier gratuit pour les images chez Google : environ 0,03 $ par image en 1K d'après la tarification consultée en octobre 2026, à revérifier) ; gardez une limite et un code d'accès ;
   - `YOUTUBE_API_KEY` (optionnel, recherche de vidéos) : activez « YouTube Data API v3 » dans la console Google Cloud puis créez une clé (une recherche coûte 100 unités sur un quota gratuit de 10 000 par jour) ;
   - `ACCESS_CODE` (recommandé) : code partagé, saisi dans la rubrique 3 ; sans lui, toute personne connaissant l'adresse peut consommer vos quotas. `ACCESS_CODES` (à la place) : un code par personne, au format `prénom:code,prénom:code` ; chacun a alors ses propres limites ;
   - `AI_DAILY_LIMIT` (défaut 150), `EXT_DAILY_LIMIT` (recherche de livres, défaut 300), `YT_DAILY_LIMIT` (vidéos, défaut 100) : appels par jour et par personne, `0` = sans limite (à écrire explicitement : une valeur vide, illisible ou négative revient à la valeur par défaut, jamais à « sans limite »). Sans stockage partagé, ces compteurs sont propres à chaque instance du serveur (approximatifs) ; pour des compteurs exacts, ajoutez `KV_REST_API_URL` et `KV_REST_API_TOKEN` (Upstash Redis via Vercel Marketplace : seule une empreinte du code d'accès est stockée) ;
   - `GOOGLE_BOOKS_KEY` (facultatif) : quota Google Books plus large pour la recherche de livres ; `BOOKS_CONTACT` (facultatif) : adresse de contact transmise à Open Library dans l'en-tête User-Agent, comme il le demande (rien n'est envoyé si vous ne la renseignez pas).
3. Redéployez. Sans clé, l'IA affiche « Configuration requise » ; les vidéos peuvent toujours être ajoutées en collant une adresse YouTube. La recherche de livres en ligne ne demande aucune clé.
4. Les en-têtes de sécurité sont dans `vercel.json` (CSP, anti-iframe, permissions) et reproduits en local par `vite preview`. Si vous activez un jour le cercle d'amis avec Supabase, ajoutez l'adresse de votre projet à `connect-src` : la CSP actuelle interdit tout appel direct du navigateur vers un autre site.

## Installer sur le téléphone
- Android (Chrome) : menu ⋮, puis « Installer l'application ».
- iPhone et iPad (Safari uniquement) : Partager, puis « Sur l'écran d'accueil ».

## IA (API Gemini)
La fonction `api/ai.ts` appelle l'API Gemini (texte, photos, réponses JSON) ; la clé reste côté serveur, jamais journalisée. Limite indicative : 20 requêtes / 10 min / IP (par instance).
Confidentialité : selon les conditions de l'API Gemini, les échanges du niveau gratuit peuvent servir à améliorer les produits Google (relecture humaine possible), pas ceux du niveau payant ; ces conditions prévoient aussi que dans l'EEE, en Suisse et au Royaume-Uni les règles du service payant s'appliquent aux services gratuits. Vérifiez les conditions en vigueur et, pour des données de santé (photos de repas, poids), préférez un projet avec facturation activée.

## Confidentialité
Données en localStorage, polices système. Rien n'est envoyé à l'IA sans consentement explicite et action de l'utilisateur. Les vidéos passent par le lecteur youtube-nocookie.com (YouTube reçoit l'adresse IP à la lecture).

## Sécurité et vie privée (état réel)
- **Rien ne part sans action explicite.** Neuf accords distincts (IA, photos, santé, GPS, mouvement, micro, dictée vocale, notifications, partage) sont demandés au moment d'utiliser la fonction concernée et retirables dans la rubrique 5 ; un refus ne bloque pas le reste de l'application. Retirer le GPS pendant une séance l'arrête (après confirmation).
- **PIN à 4 chiffres** : haché avec PBKDF2-SHA-256 (210 000 itérations) et un sel aléatoire de 16 octets, jamais stocké en clair ; 5 erreurs permises, puis blocage de 30 s doublé à chaque échec (plafond 15 min) ; le compteur est écrit avant la vérification et le blocage survit au rechargement ; pendant un blocage, même le bon PIN est refusé. Verrouillage réellement appliqué à l'ouverture, au retour dans l'application après le délai choisi (ou dès la sortie de l'écran) et après inactivité ; l'écran de verrouillage remplace toute l'interface (aucune donnée personnelle dans la page). « PIN oublié » = effacement complet des données de l'appareil.
- **Limite à connaître** : le PIN verrouille l'interface, il ne chiffre pas les données. Quelqu'un qui peut lire le stockage du navigateur (ou contourner l'application avec les outils de développement) lit les données. Le chiffrement des données par le PIN n'est pas fourni. Un PIN à 4 chiffres reste faible face à une attaque hors ligne sur l'empreinte ; la limitation des tentatives ne s'applique qu'à l'interface.
- **Droit à l'oubli** : « Tout supprimer » efface le stockage local (données, PIN, code d'accès) et la base IndexedDB (enregistrements audio, images), arrête les séances en cours, puis vérifie. Il n'est annoncé réussi qu'une fois la suppression confirmée. Ce que Google conserve éventuellement des échanges avec l'IA ne peut pas être effacé depuis Believe.
- **Pages légales** (CGU, politique de confidentialité, transparence IA) : modèle à faire relire par un juriste. Renseignez `PUBLISHER` dans `src/legal.ts` (nom, contact) avant toute mise en ligne publique ; tant que c'est vide, la page affiche « à renseigner ».
- Le PIN et les accords nécessitent un contexte sécurisé (HTTPS) pour `crypto.subtle` ; sans cela, l'activation du PIN est refusée avec un message explicite.

## Rubriques 1, 2 et 4 : profil, interface, verset du jour et prières
- **Verset du jour** : une fenêtre s'ouvre à la première ouverture de chaque jour, **une seule fois par jour** (fermée par « Continuer » ou Échap, elle ne revient pas à la réouverture ; elle revient le lendemain, y compris au retour dans l'application restée ouverte). Sous l'écran du PIN, ni verset ni donnée n'apparaissent : la fenêtre s'ouvre après le déverrouillage. Le verset reste affiché sur l'accueil avec sa **référence**, sa **traduction** et son statut (domaine public). « Nouveau verset » passe au suivant de la liste du profil, l'enregistre et revient au début après le dernier ; « Écouter » lit le texte puis la référence (bouton absent si le navigateur n'a pas de synthèse vocale).
- **Liste des versets** : 28 pour le profil Femme, 29 pour le profil Homme (sans profil, la liste complète est proposée). **C'est une sélection reconstituée, pas une liste fournie par le cahier des charges** : chaque verset a été vérifié mot pour mot contre des éditions numériques intégrales du domaine public, la Bible Louis Segond 1910 (par défaut) et la Bible Martin 1744 (pour les versets qui l'indiquent). Les seules retouches typographiques admises sont décrites en tête de `src/verses.ts`.
- **Contrôler ou compléter la liste** : `npm run verify:verses` télécharge les deux éditions (dépôt ouvert « Holy-Bible-XML-Format », réseau nécessaire) et compare chaque verset ; avec des fichiers déjà téléchargés : `node scripts/verify-verses.mjs --lsg=FrenchBible.xml --mar=FrenchMartinBible.xml`. Le script échoue au moindre écart (mot différent, verset introuvable, extrait coupé en milieu de phrase, doublon). Pour ajouter un verset, ajoutez-le dans `src/verses.ts` puis relancez le contrôle ; un psaume dont l'édition numérique compte le titre dans le verset 1 doit aussi figurer dans la table de décalage du script. Dernier contrôle exécuté ici, sur les éditions fournies en fichiers : 57 versets identiques.
- **Mur de prières et gratitudes** : sujets de prière et gratitudes (libellé et groupe distincts), cochage « Exaucée » avec date, modification, suppression après confirmation, 1 000 éléments au plus ; rien ne part sur le réseau, les données suivent l'export et l'import JSON, et les sujets de prière ne sont jamais partageables.
- **Profil, accueil guidé et interface** : voir la page « État des fonctionnalités » (menu des rubriques, adresse `#/statut`) pour le détail de ce qui est fait et de ce qui ne l'est pas ; les 60 images par seconde et le retour haptique n'ont pas pu être mesurés sans téléphone.

## Rubrique 3 : Believe AI et dictée vocale
- **Où** : rubrique 3, cinq modes (nutrition, sport, éloquence, dictionnaire, spirituel). L'accord « Believe AI » est demandé avant le premier envoi ; le contexte (âge, taille, poids, niveau, habitudes du jour) n'est joint que si vous cochez la case. Les réponses sont étiquetées « Généré par IA ».
- **Dictée vocale** : le bouton « Dicter » (sous le champ de saisie) remplit la question avec votre voix. Il utilise la **reconnaissance vocale du navigateur** (API Web Speech), pas un service de Believe : **selon le navigateur (Chrome, Safari), le son est envoyé à Google ou à Apple pour être transcrit**. Believe ne reçoit que le texte, ne garde aucun enregistrement et **n'envoie rien à l'IA tant que vous n'appuyez pas sur « Envoyer »** : le texte dicté s'ajoute au champ (espace, majuscule en début de phrase), vous le relisez et le corrigez. Un accord distinct « Dictée vocale » est demandé au premier clic (explication affichée avant tout, « Plus tard » ne change rien) ; il est indépendant de l'accord « Microphone » du dictaphone, dont l'audio reste sur l'appareil. Il se retire dans la rubrique 5.
- **Comportement** : une phrase par clic (l'écoute s'arrête après une pause), texte provisoire affiché à part (non lu par les lecteurs d'écran), état annoncé (« Préparation du micro… », « Dictée en cours… », « Texte dicté ajouté… »), messages clairs pour un micro refusé, une absence de voix, un micro introuvable, un service injoignable ou une langue non prise en charge. Le micro est coupé dès que vous envoyez, quittez la page, la masquez ou lancez une nouvelle conversation ; « Arrêter la dictée » garde le dernier résultat. Un texte qui dépasserait 4 000 caractères n'est pas ajouté (rien n'est coupé en silence).
- **Limites** : la dictée n'existe que si le navigateur fournit la reconnaissance vocale (absente de Firefox, par exemple) ; le message le dit. Elle a besoin du micro et, selon le navigateur, d'une connexion. **La reconnaissance elle-même n'a pas pu être essayée avec une vraie voix** depuis cet environnement : les tests pilotent un moteur simulé (début, résultats provisoires et définitifs, erreurs, fin), puis laissent le vrai moteur de Chromium se lancer sans micro : il répond « aucun micro », l'application affiche son message et ne se fige pas. Rien n'a été essayé sur iPhone : Safari peut exiger que la dictée soit activée dans les réglages de l'appareil, et le fonctionnement dans une application ajoutée à l'écran d'accueil n'est pas garanti.
- **Vérifications** : 41 tests (calcul d'ajout du texte, parcours d'interface avec un moteur simulé, textes de la politique de confidentialité et de la page d'état) ; audit (600 cas au hasard du calcul d'ajout, limite identique à celle de la fonction serveur, chaque accord validé un à un par le schéma, anciennes données sans l'accord « dictée » lues comme « refusé ») ; 2 parcours dans un vrai Chromium (moteur simulé : accord, écoute, texte ajouté, envoi par le bouton seulement, micro relâché, focus clavier, accessibilité dans les trois thèmes ; puis moteur réel). 60 défauts introduits volontairement dans le code (majuscule, espaces, limite de 4 000 caractères, accord contourné ou donné d'avance, micro gardé ouvert, texte provisoire traité comme définitif, destination du son non dite, focus perdu, état annoncé, message resté affiché après l'envoi…) ont tous fait échouer au moins un test, plus 12 dans le parcours Chromium ; un seul, la validation de l'accord au chargement, est attrapé par l'audit et non par les tests d'interface.

## Rubrique 5 : bilan hebdomadaire, badges, partage avec des amis
- **Où** : rubrique 5, onglets *Bilan* (par défaut), *Partage*, *Confidentialité*, *Réglages*, *Données*. Le lien `#/5/partage` ouvre directement le partage.
- **Bilan de la semaine** : calculé sur l'appareil, du lundi au dimanche, jours à venir exclus. Taux de réussite des habitudes, comparaison avec la dernière semaine archivée, habitude la plus régulière, jours à 10 000 pas, séances et distance, quiz, exercices, improvisations, pages lues, variation de poids (privée : floutée en mode discret). Rien n'est envoyé.
- **12 badges** (Premier pas, 7 et 30 jours de suite, semaine à 80 %, 10 000 pas, 5 et 10 km, livre terminé, quiz sans faute, 10 quiz, 7 jours d'exercices, 10 improvisations) : chacun a son critère écrit et se calcule sur vos données réelles. **Aucun ne dépend du poids, du cycle, des repas, des prières ni des notes** (vérifié par un test).
- **Partage avec des amis, mode local** : Believe fabrique une **carte** (image PNG de 1080 px dessinée sur l'appareil avec Canvas, et texte) avec les seuls éléments cochés ; c'est vous qui l'envoyez, par le menu de partage du téléphone (image comprise quand le navigateur accepte les fichiers, texte sinon), par téléchargement de l'image ou par copie du texte. Believe n'envoie rien lui-même et ne sait pas si la carte a ensuite été envoyée : il le dit, il ne l'annonce jamais.
- **Tout est masqué par défaut** (opt-in). Visible sur sélection : prénom, habitudes (taux et plus longue série, jamais leur nom), badges, pas et distance sans carte, scores de quiz, lectures en cours. **Sensibles, avec une confirmation par élément** : poids (départ, actuel, objectif), progression vers l'objectif de poids (pourcentage seul), cycle ou récupération du jour, calories et repas du jour, sujets de prière, nombre de notes par catégorie. **Jamais partagés** : tracé GPS (Believe ne l'enregistre pas), texte et titres des notes, audios, photos, échanges avec l'IA, PIN, détail des pesées, nom des habitudes.
- **Vue Ami** : l'aperçu montre exactement les lignes de la carte, du texte et de l'image (les trois viennent de la même liste de lignes). Un consentement « Partage » dédié et révocable est demandé avant tout ; la révocation remet tout en masqué et retire l'accord (un nouvel accord ne rend rien visible).
- **Comment le filtrage est garanti** : une seule fonction (`buildShare`, `src/share.ts`) décide de ce qui peut sortir ; une catégorie masquée n'existe pas dans la carte (clé absente), qui est ensuite vérifiée en liste blanche stricte avant l'image, le texte, la copie ou le partage. L'image porte l'identité de la carte dont elle vient : si la sélection change, l'ancienne image n'est plus ni montrée ni partageable.
- **Vérifications** : audit (état rempli de données-pièges dans chaque catégorie sensible : chaque case cochée seule, 300 combinaisons au hasard, carte refusée au moindre champ inattendu, texte dessiné ⊂ lignes de l'aperçu, changement d'heure) ; 21 tests d'interface ; test dans un vrai Chromium (image PNG réellement dessinée et décodée, fichier reçu par un menu de partage simulé, texte dessiné enregistré, aucune requête réseau, accessibilité dans les trois thèmes). 42 défauts introduits volontairement (case ignorée, nom d'habitude ou titre de note ajouté, badge qui lit le poids, image dessinée avec tout, révocation incomplète…) ont tous fait échouer au moins un test (série réalisée avant la reconstruction de l'environnement de développement : ses fichiers n'ont pas été conservés et elle ne peut pas être rejouée depuis ce dossier).
- **Limites** : le **cercle d'amis par invitation** (option Cloud/Supabase du cahier des charges) **n'est pas implémenté** : il n'y a donc ni serveur, ni compte, ni filtrage serveur (RLS) à tester ; le partage est local uniquement. Une carte déjà envoyée reste chez son destinataire : la révocation arrête tout nouveau partage, elle ne reprend rien. Le menu de partage avec fichier dépend du navigateur (le test utilise un menu simulé qui relit le fichier reçu ; rien n'a été essayé sur un vrai téléphone). La semaine est archivée à la première ouverture de l'application le lundi suivant.

## Rubrique 8 : santé, suivi du cycle ou de la récupération, recettes
- **Où** : rubrique 8, onglets *Poids*, *Eau et sommeil*, *Cycle / récupération*, *Repas*, *Scanner*, *Recettes*. L'accord « Santé et poids » est demandé au premier usage ; le suivi est **désactivé par défaut**.
- **Cycle et énergie** : vous saisissez le premier jour des règles (jamais dans le futur, jamais plus de cinq ans en arrière, 400 dates au plus) ; Believe en déduit le jour du cycle, la phase (règles, folliculaire, fenêtre d'ovulation probable, lutéale), la durée moyenne des 6 derniers cycles plausibles (15 à 60 jours ; 28 jours sans donnée) et une date estimée des prochaines règles. L'énergie ressentie se note de 1 à 5 par jour ; la moyenne par phase n'apparaît qu'à partir de 3 notes. **Ce ne sont que des repères moyens** : ni diagnostic, ni contraception, ni aide à la fertilité.
- **Récupération, force et vitalité** (autre mode) : trois notes de 1 à 5 par jour, moyennes sur 7 jours. Trois jours de suite notés avec une récupération de 2 ou moins déclenchent un repère « Récupération basse » (aussi sur la page Sport, avec un lien) qui invite à alléger la séance ; il ne bloque rien. Les deux suivis ont des notes séparées : changer de mode n'efface rien ; « Effacer mes notes et dates » demande une confirmation. 4 000 jours notés au plus.
- **Partage** : seule une ligne (« Jour N du cycle · énergie E sur 5 » ou « Récupération R sur 5 · force F sur 5 · vitalité V sur 5 ») peut figurer sur la carte, case sensible décochée par défaut ; les dates de règles ne sortent jamais.
- **Image du plat (à la demande)** : chaque recette proposée a un bouton « Générer l'image du plat ». Il n'envoie au serveur que le **titre et les ingrédients** de la recette (ni profil, ni repas, ni photo), qui interroge l'API d'image de Gemini (`gemini-nano-banana-2.1` par défaut, variable `AI_IMAGE_MODEL`). L'image est une illustration étiquetée « Généré par IA » (filigrane invisible SynthID ajouté par Google) ; elle peut différer du plat réel. Elle n'est **ni enregistrée ni partagée** : elle disparaît avec la liste de recettes (nouvelle recherche, changement de page). Limites : 6 images par 10 minutes, `AI_IMAGE_DAILY_LIMIT` par jour (20 par défaut), délai de 50 s côté serveur (fonction limitée à 60 s dans `vercel.json`), une image à la fois par recette, annulable. **Coût et réserve** : service payant sans palier gratuit ; le format de la requête suit la documentation de Google consultée en octobre 2026 mais n'a pas pu être essayé avec une vraie clé depuis cet environnement : testez une image après le déploiement et vérifiez le nom du modèle et le tarif dans Google AI Studio.
- **Vérifications** : calculs de cycle testés dans trois fuseaux horaires (dont changement d'heure), tests d'interface, parcours dans un vrai Chromium (images servies par interception réseau, CSP appliquée, axe-core dans les trois thèmes) et défauts introduits volontairement dans le code, tous détectés (ceux qui touchent aux dates ne se voient que dans certains fuseaux horaires : voir la dernière section).

## Rubrique 9 : tâches, quadrants et rappels locaux
- **Où** : rubrique 9 « Professionnel et calendrier » : Pomodoro, tâches classées en quatre quadrants (urgent = échéance dans moins de 48 h ou dépassée, important = case cochée, quadrant modifiable à la main), rappels, export `.ics` (Apple Agenda, Google Agenda, Android ; alarme 30 minutes avant) et lien « Google Agenda » prérempli par tâche.
- **Rappels (désactivés par défaut)** : la carte « Rappels » demande l'accord « Notifications » au clic sur « Activer les rappels » ; c'est à ce même clic, et seulement là, que le navigateur peut demander l'autorisation des notifications du système (bouton « Autoriser les notifications du système » si elle n'a pas été donnée). **Un refus du navigateur n'empêche pas les rappels dans l'application** et le dit. Délai réglable : à l'heure de l'échéance, 10 min, 30 min (par défaut), 1 h ou 2 h avant. Un bouton « Tester une notification » vérifie la chaîne complète.
- **Fonctionnement** : le calcul se fait sur l'appareil, **sans serveur ni Web Push**. Au démarrage, toutes les 30 s, au retour au premier plan et à chaque modification de tâche ou de réglage, Believe cherche les tâches non terminées dont le moment de rappel (échéance moins le délai) est atteint, jusqu'à 12 h après l'échéance (au-delà, la tâche est simplement en retard : pas de rafale à la réouverture après plusieurs jours). **Au premier plan** : bandeau dans l'application, annoncé aux lecteurs d'écran, avec un lien vers les tâches. **En arrière-plan ou sous l'écran du PIN** : notification du système si le navigateur l'autorise, **sans le titre de la tâche en mode discret ou sous le PIN** (« Believe : rappel, Une tâche arrive à échéance ») ; sinon rien n'est marqué et le rappel s'affiche au retour dans l'application. Un rappel n'est marqué « donné » qu'une fois réellement affiché, **une seule fois par échéance** (changer l'échéance en redonne un). Une tâche créée alors que son moment de rappel est déjà passé ne sonne pas aussitôt. Le clic sur une notification ramène à la rubrique 9 (`public/sw-notify.js`, chargé par le service worker ; seules les adresses du site sont acceptées).
- **Limites à connaître** : **un rappel n'est donné que pendant que Believe est ouvert** (au premier plan, ou en arrière-plan tant que le navigateur garde la page active : Android et iOS suspendent souvent les pages inactives au bout de quelques minutes, surtout écran verrouillé). Application fermée, rien ne sonne ; pour être prévenu quand même, exportez les tâches en `.ics` : c'est alors l'agenda qui alerte. Sur iPhone et iPad, les notifications du système exigent Believe installé sur l'écran d'accueil (iOS 16.4 ou plus récent) ; sinon seul le bandeau existe. Un vrai Web Push (rappel application fermée) demanderait un serveur de notifications et des abonnements : il n'est pas fourni. Le texte de la notification s'affiche aussi sur l'écran verrouillé de l'appareil selon ses réglages : activez le mode discret si vous ne voulez pas y voir vos titres de tâches.
- **Vérifications** : 20 tests d'interface des rappels et 20 tests du clic sur la notification (`public/sw-notify.js`, adresses hostiles refusées) ; audit (fenêtre de rappel, tâches terminées ou sans échéance, une seule fois par échéance, texte de l'échéance indépendant du fuseau et du changement d'heure, repli quand le service worker échoue, lien entre le service worker généré et `sw-notify.js`) dans trois fuseaux horaires ; un parcours dans un vrai Chromium avec un vrai service worker (bannière au premier plan, notification du système en arrière-plan, texte neutre en mode discret, une seule fois par échéance, aucune requête réseau, accessibilité dans les trois thèmes). Des défauts introduits volontairement ont tous été détectés : 30 dans l'interface, 22 (et 1 selon le fuseau) dans le calcul, 15 dans le clic sur la notification, 11 dans Chromium. **Réserve** : sur Chromium sans écran, la liste des notifications du système est parfois vide juste après l'affichage (observé dans quelques pour cent des essais en répétant le test) ; le test s'appuie donc sur le journal des appels de l'application et ne traite cette liste que comme une vérification souple.

## Rubrique 11 : notes, dictaphone, prompteur, métronome
- **Notes** : 5 catégories (Rêves, Cauchemars, Chants, Poèmes, Apprentissages), recherche plein texte sans accents ni majuscules avec surlignage, catégories par puces visibles ou par balayage. Créer une note « Apprentissages » coche l'habitude « Apprendre une chose », « Chants » ou « Poèmes » coche « Activité créative » (message explicite ; décochable dans Habitudes). Pour un cauchemar, « Apaisement et prière (IA) » affiche le texte exact qui sera envoyé (3 000 premiers caractères) et ne l'envoie qu'après l'accord IA **et** un clic ; la réponse est marquée « Généré par IA » et n'est ajoutée à la note que sur demande.
- **Dictaphone** : `MediaRecorder` (webm/opus sur Chrome, mp4/aac sur Safari), 10 minutes maximum, écoute avant sauvegarde, stockage IndexedDB (`BelieveAudioDB`, magasin `audios` + descriptions légères `audioMeta`, relus au démarrage), renommage, téléchargement d'une copie, suppression vérifiée. Le micro n'est demandé qu'au clic sur « Enregistrer » et relâché à l'arrêt ; l'enregistrement continue si l'on change de rubrique (bandeau). **Limite** : un navigateur peut effacer les données d'un site quand l'appareil manque de place (Safari : après 7 jours sans visite, sauf application installée sur l'écran d'accueil). Les audios ne figurent pas dans l'export JSON : utilisez « Télécharger » pour garder une copie.
- **Prompteur** : texte modifiable (conservé sur l'appareil), vitesse (5 à 300 px/s) et taille (14 à 96 px) réglables en direct, plein écran, lecture d'une note, écran maintenu allumé pendant le défilement.
- **Métronome** : 30 à 240 battements/min, mesure à 2, 3, 4 ou 6 temps (premier temps plus aigu), frappe du tempo, rythme visuel si les sons sont coupés. Il s'arrête quand l'application quitte l'écran : un navigateur ne garantit pas un son régulier en arrière-plan.

## Rubrique 12 : bibliothèque et recherche de livres
- **Catalogue intégré** : 33 livres en 5 catégories (Classique, Développement personnel, Manipulation & Persuasion, Biblique, Art de la rhétorique), en français et en anglais. Chaque fiche contient un résumé **original** (idée centrale, points clés, à retenir, résumé en anglais), des liens de lecture ou d'écoute **légaux** et, uniquement pour les œuvres du domaine public, une citation courte avec sa référence (vérifiée). Aucune citation ni texte n'est reproduit pour une œuvre protégée. La recherche (titre, auteur, thème, mot-clé, langue ; sans accents ni majuscules ; tous les mots requis ; surlignage) se fait sur l'appareil, sans réseau.
- **Recherche en ligne** : Open Library, Google Books, Project Gutenberg (via Gutendex) et LibriVox, interrogés par la fonction serveur `api/ext.ts`. Seuls le texte saisi, la langue et les catalogues choisis partent, **et seulement après un clic sur « Chercher en ligne »**. Les résultats sont contrôlés à l'arrivée (adresses limitées aux domaines autorisés, champs bornés), classés (accès libre, emprunt, extrait, fiche) et chacun indique clairement son accès légal. Les audio viennent de LibriVox (lecteurs bénévoles, domaine public). Un catalogue en panne n'empêche pas d'afficher les autres. Pour Project Gutenberg, le statut « domaine public » est celui des États-Unis : la règle peut différer dans votre pays (c'est dit à l'écran).
- **Couvertures** : désactivées par défaut. Si vous les activez, elles sont chargées directement depuis les sites des catalogues (qui voient alors votre adresse IP, sans référent) ; sinon une tuile colorée aux initiales du livre est affichée. La CSP n'autorise les images que de ces domaines.
- **Mes livres** : ajout depuis le catalogue, depuis un résultat en ligne ou à la main ; statut (À lire, En cours, Terminé), nombre de pages facultatif, marque-page. Le marque-page est le même que celui de l'habitude « 20 pages de mon livre » (rubrique 6) : les pages saisies d'un côté apparaissent de l'autre, l'habitude est cochée automatiquement à 20 pages (même renommée) et se décoche à la main.
- **Fiche de synthèse par Believe AI (à la demande)** : le texte exact qui sera envoyé (titre, auteur, descriptif du catalogue s'il existe) est affiché ; il faut l'accord « IA » **et** un clic ; ni profil, ni notes, ni progression ne partent. La fiche est signalée « Généré par IA » avec le modèle et la date, et n'est gardée avec le livre que sur demande.
- **Lecture vocale** : voix de l'appareil (aucune donnée envoyée), par morceaux courts, en français ou en anglais.
- **Limites** : la fiche IA et les appels réels aux catalogues n'ont pas été exécutés ici (réponses simulées) ; le contenu des catalogues dépend des services extérieurs ; les livres audio ne sont proposés que par des sources légales.

## Rubrique 13 : académie d'éloquence, quiz, improvisation
- **Exercices (5 par jour)** : 72 exercices en 6 familles (diction, articulation, souffle, figures de style, répartie, posture vocale), cinq familles différentes chaque jour. Chaque exercice a son texte ou sa consigne, ses étapes, un conseil, un **chrono dédié** (durée conseillée, réglable par pas de 15 s ; le temps suit l'horloge, pas le nombre de ticks ; signal sonore et vibration à la fin si les réglages les autorisent) et une **auto-écoute** (« M'enregistrer », « Arrêter et m'écouter »). « Fait » ne se coche que sur clic (et se retire) ; la série compte les jours consécutifs.
- **Auto-écoute** : le micro n'est demandé qu'au clic (accord « Micro » distinct), il est relâché à l'arrêt, l'enregistrement reste sur l'appareil (5 minutes maximum) et il est **supprimé dès qu'on quitte l'exercice**, sauf si l'on appuie sur « Garder dans le dictaphone » (rubrique 11, catégorie Apprentissages, suppression vérifiée comme les autres audios). Quitter l'exercice (ou changer de rubrique) arrête l'enregistrement en cours et relâche le micro.
- **Anti-répétition persistante** : chaque exercice proposé est mémorisé (fenêtre glissante des 55 derniers : un exercice ne revient pas avant 11 jours) ; le lot du jour est stable après rechargement ; un jour sans ouverture ne consomme aucun exercice. Pour les quiz, chaque question attribuée est mémorisée **par identifiant et par empreinte de son texte** et contrôlée avant affichage ; pour l'improvisation, les 1 000 derniers sujets le sont. Tout reste sur l'appareil.
- **Quiz** : 136 questions (Vocabulaire, Définitions, Rhétorique, Culture générale, Biblique), soit environ 27 quiz avant épuisement. Quiz du jour de 5 questions (un thème chacune tant que possible), quiz par thème, une question à la fois, explication et bonne réponse montrées après chaque réponse (couleur **et** texte), score, historique, reprise après interruption, abandon (sans historique ; les questions déjà attribuées ne reviennent pas). L'habitude « Apprendre une chose » n'est cochée qu'à la fin d'un quiz, avec message. Une question générée ou intégrée n'est jamais comptée deux fois.
- **Quand la banque est épuisée** : l'application le dit (« Vous avez vu toutes les questions disponibles »), propose une **révision** (questions déjà vues, sans effet sur les statistiques) ou des questions écrites par Believe AI **sur demande** : texte exact montré, accord « IA » et clic requis, seule la catégorie part, quatre réponses distinctes contrôlées, doublons écartés, questions signalées « Généré par IA » (à vérifier, une IA peut se tromper).
- **Improvisation infinie** : sujets composés (71 280 combinaisons), jamais repris, un thème n'est pas repris dans les trois tirages suivants, **note de difficulté de 1 à 5 sous chaque sujet** avec la raison de la note, durée 1, 2, 3 ou 5 minutes (ou réglable), chrono, auto-écoute, historique. **« Conseil Believe AI » sur demande** : le texte exact (le sujet et une consigne) est affiché, accord « IA » et clic requis, aucune donnée personnelle, conseil non enregistré.
- **Limites** : les réponses réelles de Gemini n'ont pas été obtenues ici (réponses simulées pour vérifier les requêtes envoyées et le contrôle des réponses) ; le son de fin de chrono, la vibration, le micro et la lecture d'un vrai téléphone (Android, iPhone) ne sont pas testés ; la banque de questions a été écrite pour l'application et relue, mais pas validée par un enseignant ; les 72 exercices sont des consignes de pratique, pas une évaluation de votre diction (l'application n'analyse pas votre voix).

## Défauts introduits volontairement (qualité des tests)
`scripts/mutation/run.py` remplace un morceau de code par une version volontairement fautive, lance les tests visés, puis remet le code d'origine : le défaut doit faire échouer au moins un test (**DÉTECTÉ**). **SURVÉCU** signale un test manquant ; **ANCRE INTROUVABLE** signale que le code a changé depuis l'écriture du défaut.

`python3 scripts/mutation/run.py scripts/mutation/specs/dictee.json [filtre sur le nom]` (ne modifiez aucun fichier pendant une série ; pour les séries Chromium, le port 4173 doit être libre et l'application est reconstruite à chaque défaut ; les défauts des séries `*-fuseaux.json` dépendent du fuseau horaire : jouez-les dans `TZ=Europe/Paris`, `TZ=America/Los_Angeles` et `TZ=Pacific/Auckland`, chacun doit être détecté dans au moins un).

(2) Un défaut équivalent (V8, fenêtre du verset non fermée au verrouillage) a été retiré : il ne change aucun comportement visible, puisque le déverrouillage rouvre de toute façon la fenêtre qui n'avait pas été fermée.
